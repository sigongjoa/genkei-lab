**보내기 · 받기 (09-22):** 파일 붙이기가 ChatGPT 에서 칩으로 안 떠서 묶음 본문을 입력창에 그대로 넣고 질문을 붙였다(같은 내용).
GPT · Gemini 는 처음 누른 전송이 먹지 않아 탭을 앞으로 가져와 다시 눌렀다. Grok(빠른) 답은 ② 중간에 끊겨 성공 숫자가 없다.

**내 쪽 오류:** 없음 — 표의 숫자는 `exe벤치.json` 과 맞다. 0.769 는 채점 규약이 다르다고 적어 보냈다.

**셋이 따로 낸 같은 말 (핵심):** 부위마다 타원뿔대 **하나**면 부위 안의 높이별 굵기 변화(어깨 → 상완 → 팔꿈치 …)를 직선으로 버린다.
→ **부위별 여러 단면(타원) 로프트**로 바꿔라. GPT 5 매듭(0 · 25 · 50 · 75 · 100 %) · Gemini 5~10 제어점 · Grok 부위 안 층 타원.

**판정:** 로프트는 셋 다 냈고, ⓐⓑⓒ 를 다 통과한 것은 ChatGPT 하나 · Gemini 는 ⓐ 가 반쯤 · Grok 은 ⓒ 없음.
문턱(두 모델 이상 전부 통과)을 글자대로 읽으면 못 넘는다. **다만 착상은 셋이 같고, 측정 설계(A/B/C)와 성공 숫자는 GPT 것만 쓴다** —
「채택」이 아니라 **우리 v1 계획을 고친다**: 부위별 타원뿔대(A)는 대조로 남기고 5 매듭 로프트(B)를 본 판으로, 층 타원(C)을 대조군으로.
성공 숫자는 GPT 의 셋을 우리 예측으로 삼는다(돌리기 전 커밋).

**지적 가르기:**
- 차렷처럼 팔이 몸통에 붙으면 「몸통 폭 밖 = 팔」 규칙이 못 가른다 (Gemini · Grok) — **맞다**, 재 봐야 한다: 차렷 앞 그림에서 팔-몸통 틈 화소
- 옆 그림에서 팔이 몸통과 겹치면 깊이가 부위 두께가 아니라 겹친 두께 (Gemini) — **맞다**
- 치마 · 망토 · 긴 머리는 세 규칙에 흡수된다 (GPT · Grok) — **이미 알고 있다** (마네킹_치마 0.356)
- 폭 · 깊이를 타원 두 축으로 보는 가정은 단면이 네모면 깎인다 — 도형 동점 넷이 그 증거 (GPT) — **맞다**, 이미 잰 것
- 앱 점수와 3D 는 다르다(순위상관 0.695) — **이미 하고 있다** (그래서 exe 벤치가 3D 로 채점)
- 부위 경계 ±5~10% 변형을 후보로 (Grok 혼자) — 채택 안 함, 로프트 뒤에 싸면 해 본다

**돌려 본 뒤 (09-22, `벤치/사람형.py` 46장):** GPT 성공 숫자 셋 **다 못 넘었다** — B 중앙 0.568 (≥ 0.60 ✗) · B−A +0.147 (≥ +0.15 ✗, 아슬) ·
C−B +0.178 (≤ 0.05 ✗). 로프트(B)는 타원뿔대(A)보다 낫지만(0.421 → 0.568), 부위 없는 층 타원(C 0.745)에 한참 못 미친다.
우리 예측(층 타원이 이긴다)은 맞았다. 셋이 같이 낸 착상도 숫자 앞에서는 절반만 맞았다 — 패널은 채점용.
